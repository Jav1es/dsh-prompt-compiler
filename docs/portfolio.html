DSH Plugin · Prompt Compiler

把粗糙的 draft，编译成精确、完整、可执行的 prompt

随手写的「帮我写个爬虫」，把大量决策甩给了模型。这个插件先诊断缺什么， 再问你几个关键问题，最后合成一份带验收标准的结构化 prompt。 它同时是一个可编程的编译层，别的插件和 Agent 可以直接调用。

① 诊断 analyze→ ② 澄清 elicit→ ③ 合成 compile→ ④ 模板 render

最新一版只修一件事：不让你干等

慢和死看起来一模一样。界面纹丝不动，你不知道它是在跑还是已经挂了 —— 这是 0.4.1 唯一的主题。

三个原因叠在一起

  1. 原因 ① 模型选择盲取列表第一个 旧代码用 listModels(provider)[0]，拿到的是 hy4-preview-f —— 一次编译吐 2250~2632 个 chunk（大量 reasoning-delta）， 而会话在跑的 hy3-x 只要 28 个。
  2. 原因 ② for await 没有任何时限 宿主不结束就永远等。注意这里要两层：逐 chunk 检查只在"流吐下一个 chunk"时才有机会跑， 若宿主一个 chunk 都不吐，内层检查永远轮不到执行 —— 所以外层还得套 Promise.race。
  3. 原因 ③ 超时后还换 purpose / provider 重试 那只会再等一个 90 秒，没有任何收益 —— 慢是慢在同一个上游本身。
  4. 现在 会话当前模型 → provider 优选档 → 列表首个 且前两级都要在 listModels 清单里确认归属，不靠模型名猜 —— 否则会把 A 家的档塞给 B 家。
超时不等于失败，等于降级。 到点就给你一份规则式编译的粗糙结果，同时把发生了什么明确写进诊断：
diag.timedOut = true // 我们主动放弃（太慢），不是宿主出错
diag.timeoutNote = "模型调用超过 90 秒未完成，已放弃 LLM 链路并降级为规则式编译"
diag.modelUnavailable = "…hy3-x 未能成功调用…" // 点名是哪个模型

这三条各有 9 条测试锁死（tests/timeout.test.js）， 而且每条都用注入破坏验证过能被击穿：把 Promise.race 拿掉， 测试进程会直接挂死 —— 这本身就是"没有 deadline 就会挂住"最直接的证据。

诚实记录一条取不到的值： 宿主 ctx.llm 实际只有 ctx / name / typertRemote / adapters / directory / discoveries 这些键（已用实读 app.asar + 运行时 diag.llmKeys 双向确认）， 不暴露"当前会话模型"。所以"优先用会话当前模型"这条在本机当前版本上取不到值， 会自动退到 provider 优选档 hy3-x（实测有效）。等宿主提供该字段时无需改代码即可生效。

凭什么说这个评分不是"自说自话"

防线说明怎么验证
抗刷分 只写四个段名（## Task / ## Constraints…）的空壳必须 0 分，堆 20 倍长度也不得多拿分 tests/scoring.test.js
逐维正对照 每一条打分规则都有"有 / 无"两版输入，断言分数必须变化 —— 防止规则写了却没生效 同上
防劣化 评测集自己也有测试：真实 draft 不得被判 0 分、平均增益不得低于 +40、命中率不得低于 90% tests/eval.test.js

三条防线都用"注入破坏"验过：把代码故意改坏后对应测试会变红，还原后变绿。 一个永远打印 ✔ 的检查器比没有检查器更危险，所以这一步不做不行。

它到底解决什么问题

代码里的注释写得很诚实，这里照抄：

// 简化的分句逻辑（真实实现还处理域名/文件名/版本号里的句点）
function splitSentences(text) {
  return String(text).split(/(?<=[。！？；])\s*|\n+/)
}

但真实遇到的 bug 是这个：按 . 无条件切句，会把 news.example.com 切成「news」「example」「com 首页新闻标题」—— 证据引用变成半截，用户根本没法复核扣分理由是什么。

这个问题不是我"想到"的，是写评测集的时候当场抓出来的。 12 条真实 draft 里，「做个落地页」「优化一下」「帮我看看」全都判了 0 分 —— 而评分的落点正是这类粗糙 draft，判 0 等于告诉用户「你什么都没说」。 根因是动作动词词表只收了技术词汇（抓取/生成/修复），漏了中文最高频的「做/写/改/看看」。

类似这样被评测集抓出来的真 bug，都写在 NEXT-STEPS.md 的 F3 条目里，附带修法与回归测试。

还有一个"自己给自己扣分"的 bug

规则式编译路径（不接 LLM 时的兜底）曾经把一条 prompt 34 分改成 32 分 —— 越编译越差。查下来很荒诞：是它自己写的话被自己扣了分。 

## Constraints
- 明确、可执行、无歧义                    ← 听着像约束，其实什么都没约束

## Assumptions
- 假设无额外边界，模型在合理范围内自行决策   ← "合理"是模糊词，歧义维如实扣 2 分

修法是让缺口看起来就是缺口：没有约束就写「未提供约束，请补充：…」， 而不是塞一句正确的废话。修完后 12 条样本的规则式编译增益最小是 +20， 没有一条为负。这条现在是测试底线（底线⑤ / ⑤b），回滚代码会立刻变红。

安装

# 从 npm 安装（推荐）
dsh plugin --profile desktop add npm:dsh-prompt-compiler

# 或从 GitHub 安装
dsh plugin --profile desktop add git+https://github.com/Jav1es/dsh-prompt-compiler.git

装完后 composer 工具栏会出现「✨ 编译」入口，DSH 设置页会出现 Prompt Compiler 面板。

怎么用

给人用

在输入框写好粗糙的草稿 → 点「✨ 编译」→ 看到诊断与澄清表单 → 采用并回填。编译可随时取消，草稿一个字都不丢。

给插件与 Agent 用

// 服务：任何 inject ['promptCompiler'] 的插件都能用
const { compiled, score5d, scoreDelta } = await ctx.promptCompiler.compile(draft)

// 工具：模型可直接调用
prompt_compile({ draft: "帮我写个爬虫" })
prompt_template({ template: "portfolio-review", variables: { siteUrl, targetRoles } })

诚实披露

这一节会随着竞品调研不断收紧。凡是调研推翻了的说法，都在这里改回来，而不是悄悄删掉。

  • 不宣称「首创交互式澄清」。 yaoshuo530/dsh-prompt-enhancer（2026-08-28）已实现「判断是否需要澄清 → 澄清卡片 → 结构化提问」完整链路，早于本项目。
  • 不宣称「首创可编程 prompt 服务」。 seven282/oss-prompt-optimizer 已有 ctx.promptOptimizer 服务 + prompt_optimize 工具；SongMiao-tech 同样暴露服务。
  • 「五维评分」也不是独特名目。 Y1X1n 自称「五维诊断」，xueccci 有评分弹窗与继续优化。
  • Claude Code 侧尚未实现。跨端是方向，目前只有 DSH。

完整的 23 个竞品横向对比（star / 创建日期 / 最后推送时间 / 能力分类，全部现场查询可复现）见仓库 docs/competitor-comparison.md。

本项目真正的差异点

不是"我做得更多"，而是"我这几个数字你能自己验"：

  1. 评分规则式、确定性、零模型成本。竞品评分依赖 LLM，每次结果漂移；本项目同一输入恒得同分，可以进 CI。
  2. 公开评测集 + 可复现数字。方法和数据都在仓库里，一条命令复跑，不是一张截图说了算。
  3. 抗刷分与证据回溯是测试锁死的。空壳必须 0 分、每处扣分必须指向原文片段 —— 这两条在测试里有断言，不是宣传语。

开发

npm run verify   # ① 静态自检 ② 单测 ③ 提示词守门 ④ 宿主侧端到端
npm run eval     # 评测集：跑出上面那组 Before/After 数字
npm test         # 192 个用例

verify 分四层，各自回答不同问题：仓库形态自洽吗 / 每个模块对不对 / 装进宿主后服务与工具真的能用吗。其中「提示词守门」会双向校验 —— 系统提示里提到的工具必须已注册，已注册的给模型用的工具必须被提示过。 这类错单测、静态检查、e2e 主体都看不出来（服务能跑、路由能通，只是模型永远用不上那个工具）， 所以必须是单独一层把两边拉在一起比对。
